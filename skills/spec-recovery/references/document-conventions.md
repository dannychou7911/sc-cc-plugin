# 文件通用規範

所有 L0–L4 產出文件必須遵守以下規範。

---

## Header

每份文件開頭包含：

```markdown
# {文件標題}

> **層次**：L{0-4}
> **最後更新**：{日期}
> **分析基準**：{git short SHA}
> **狀態**：初版 / 已驗證 / 待更新
> **負責人**：{姓名或留空}
```

「分析基準」為產出當下的 `git rev-parse --short HEAD`。後續「更新既有規格」時，以 `git diff {SHA}..HEAD --stat` 判斷文件是否過期、需重新分析的範圍。

## 目錄（TOC）

Header 之後、正文之前，必須包含**目錄區塊**，列出所有一級和二級標題的連結。

```markdown
## 目錄

- [1. 章節名稱](#1-章節名稱)
  - [1.1 子章節](#11-子章節)
- [2. 章節名稱](#2-章節名稱)
```

## Confidence Markers

| 標記 | 意義 |
|------|------|
| `[確認]` | 程式碼明確顯示 |
| `[推斷]` | 合理推論 |
| `[待確認]` | 需人工確認 |
| `[未確定]` | 問過使用者但無法確定，列入 Open Questions |
| `[未確定-業務脈絡]` | 業務知識缺失，非程式碼分析不足 |

## 流程圖

一律使用 **mermaid.js flowchart 語法**繪製，不使用純文字樹狀圖。適用於 L0–L4 所有層次。

## 隱性規則標記

使用 🔴/🟡 分級標記。分級標準詳見 `implicit-rules-standard.md`。

## 敏感資料遮罩

規格文件會進入版控，絕不可包含可用的機密值。以下內容一律遮罩後才能寫入文件：

| 類型 | 遮罩方式 | 範例 |
|------|---------|------|
| API key / token / secret | 保留前綴 + `****` | `sk-****` |
| 密碼、連線字串 | 整值替換 | `{已遮罩}` |
| 內部主機名 / IP | 以角色描述取代 | `{內部 API gateway}` |
| 環境變數值 | 只記錄格式說明，不記錄真實值 | `JWT 簽章用字串（32 字元）` |

違反此規範視為格式規範不合格（列入評分 checklist）。
