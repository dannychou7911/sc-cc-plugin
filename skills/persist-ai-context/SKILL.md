# 持久化 AI 協作脈絡

先辨識專案用來管理需求、設計、決策、變更與開發任務的正式來源。只以 `.ai/` 保存必須跨 Agent、工具或工作階段延續的暫時執行脈絡，不得以本方法取代 OpenSpec、Issue、ADR、規格或其他正式系統。

## 辨識正式來源

1. 檢查目標專案使用哪些正式工作系統與文件，例如 OpenSpec、Issue tracker、ADR、規格或任務管理系統。
2. 專案若使用 OpenSpec，讀取其專案內說明並遵循對應流程；若未使用，不要自行安裝或假設必須導入。
3. 變更前先讀取目標專案的 `AGENTS.md`、`CLAUDE.md`、正式工作流程說明及既有 `.ai/*/README.md`。
4. 若專案沒有明確的正式來源，向使用者確認正式需求、決策與任務應寫入何處，不得將 `.ai/` 當作預設替代品。
5. 安裝後以目標專案的 `.ai/*/README.md` 作為操作契約。技能內建資產只是安裝預設值，不具有更高優先權。

## 初始化或遷移專案

以 `assets/project-context/.ai/` 作為可部署基準，並以 `assets/agent-startup-prompt.md` 作為 Agent 啟動指示區塊。

1. 檢查既有 `.ai/`、Agent 啟動指示及未提交變更。
2. 只建立 `.ai/handoff/`、`.ai/follow-up/` 與 `.ai/archive/`，並放入其內建 `README.md` 操作契約。
3. 保留既有專案內容，不得直接覆寫當地操作契約或工作項目。
4. 若既有規則與內建方法的衝突會改變行為、範圍或資訊責任，整理差異並由使用者裁決。
5. 將 Agent 啟動提示加入或整合至專案現有的 Agent 入口文件，避免重複加入同等指示。
6. 將正式專案知識留在專案既有的正式系統，不要遷移至 `.ai/`。
7. 驗證完成後的路徑、連結與參照，並回報仍需使用者裁決的內容。

除非使用者正式改變此方法，否則不要新增其他 `.ai` 分類、log、summary、索引或決策資料夾。

## 操作工作流程

### 開始或接續工作

1. 讀取 `.ai/handoff/README.md`，以及與目前正式工作項目相關的 handoff。掃描工作資料時排除各目錄的 `README.md`。
2. 依程式碼、Git、專案採用的正式工作系統與文件驗證 handoff 中的重要敘述。
3. 只在 follow-up 與目前工作直接相關、被明確引用、使用者要求，或準備選擇後續工作時讀取它。
4. 只在需要歷史脈絡時讀取 archive。
5. 若重要來源互相衝突，整理證據並請使用者裁決，不要自行選擇真相來源。

### 分類資訊

依資訊目前的用途選擇存放位置：

- 將下一個 Agent 或工作階段仍需延續的未完成狀態放入 `handoff/`。
- 將有保留價值、非阻斷、超出目前範圍且尚未被授權成為正式工作的事項放入 `follow-up/`。
- 將已退出當前狀態但具有歷史價值的 handoff 或 follow-up 移入 `archive/`。
- 刪除已退出當前狀態且沒有歷史價值的內容。
- 將已確認的需求、設計、決策、變更與任務寫入專案採用的正式系統；若使用 OpenSpec，依其流程處理。

記錄 follow-up 不代表授權實作或指定優先順序。若問題會阻礙目前工作，應寫入 handoff 並立即提出，不可只將它延後為 follow-up。

### 撰寫與維護記錄

1. 遵循專案當地操作契約所定義的檔名、frontmatter、必要區段與生命週期。
2. 記錄最新有效狀態、可執行的下一步與可驗證證據，不保存完整對話或內部推理。
3. 保留理解現況仍需要的結論與決策依據；省略未採用方案及討論過程。
4. 明確區分已確認事實、未驗證假設、部分驗證及無關的既有失敗。
5. 引用專案採用的正式來源，不重複保存其內容。
6. 同一事項已存在時更新原文件，不建立重複項目。
7. 不得保存密碼、token、個資或其他敏感資訊。

### 結束或交接工作

1. 工作必須跨工作階段延續，且狀態或下一步已有實質變化時，更新目前 handoff。
2. 只將符合條件的延後發現記錄為 follow-up。
3. 確認正式結果已反映至程式碼與專案採用的正式系統。
4. 依專案當地操作契約，封存或刪除已退出使用狀態的記錄。
5. 確保每個工作項目只存在於一個目前生命週期位置。

## 審閱方法落實情況

確認下列事項：

- `.ai/` 沒有取代專案採用的正式工作系統；專案若使用 OpenSpec，仍遵循其流程。
- 除非使用者已正式採用擴充，`.ai/` 只包含 `handoff/`、`follow-up/` 與 `archive/`。
- 每個目錄都有操作 `README.md`，且工作資料掃描會排除這些檔案。
- 進行中的記錄仍符合目前專案證據。
- Follow-up 仍屬延後候選事項，沒有變成未授權的影子任務。
- Archive 是歷史快照，不被當作目前事實。
- 重複、過期、已正式化或沒有保留價值的記錄，已依情況正式化、封存、合併或移除。

若衝突會影響需求、行為、範圍、資訊責任或下一步，必須先由使用者裁決。

## 維護可攜技能

當此技能與本方法的正式 `.ai/*/README.md` 位於同一個來源專案時：

1. 先更新專案內的正式操作契約。
2. 將三份契約同步至 `assets/project-context/.ai/`。
3. 逐份確認內建契約與專案正式來源完全一致。
4. 正式 Agent 啟動指示改變時，同步更新啟動提示資產。
5. 每次工作流程發生實質變更後，重新驗證技能。

## 工具相容性

- 保持 `SKILL.md` frontmatter 只含 `name` 與 `description`，維持 Codex 與 Claude Code 可共用的 Agent Skills 格式。
- 在 Codex 中，將完整技能目錄放入已設定的技能目錄，並以 `$persist-ai-context` 呼叫。
- 在 Claude Code 中，將完整技能目錄放入 `.claude/skills/persist-ai-context/` 或 `~/.claude/skills/persist-ai-context/`，並以 `/persist-ai-context` 呼叫。
- `agents/openai.yaml` 只提供 Codex 介面 metadata；Claude Code 不依賴此檔案。技能的核心流程與可攜資產不得依賴它。
