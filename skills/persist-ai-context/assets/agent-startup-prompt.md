## AI 持久化專案脈絡

本專案使用 `.ai/` 保存 AI 執行工作時，跨 Agent、工具與工作階段延續所需的工作狀態。

`.ai/` 不管理正式需求、設計、決策、變更或開發任務，也不得取代專案採用的 OpenSpec、Issue、ADR、規格文件或其他正式系統。

開始或接續工作時：

1. 檢查 `.ai/`，並辨識專案採用的正式資訊來源；若有 OpenSpec，一併讀取其專案說明。
2. 讀取 `.ai/handoff/README.md`，並檢查與目前工作相關的 handoff。
3. 依程式碼、Git、正式工作系統與文件驗證 handoff 的內容。
4. 只在目前工作相關、handoff 明確引用，或使用者準備選擇後續工作時檢查 `.ai/follow-up/`。
5. 只在需要追溯歷史脈絡時讀取 `.ai/archive/`。
6. 掃描工作資料時排除各目錄的 `README.md`；`.ai/*/README.md` 是操作方法的真相來源，不是工作項目。

工作進行及結束前：

- 尚需跨 Agent 或工作階段延續的目前狀態，依 `.ai/handoff/README.md` 建立或更新 handoff。
- 不屬於目前範圍、不需立即處理且尚未正式化的候選事項，依 `.ai/follow-up/README.md` 記錄；記錄不代表已授權執行。
- 使用者確認執行 follow-up 後，將它納入專案既有的正式工作流程；若使用 OpenSpec，建立或更新對應 change。
- 已退出當前狀態且具有回溯價值的內容，依 `.ai/archive/README.md` 封存。
- 正式需求、設計、決策、變更與開發任務必須寫入專案採用的正式系統，不得只保留於 `.ai/`。
- 如果 `.ai` 與程式碼、Git、正式工作系統或文件出現會影響需求、行為、範圍或下一步的衝突，整理證據並向使用者確認，不自行裁決。
